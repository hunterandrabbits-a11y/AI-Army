新增一个数字人，要动数班的哪些模块

新岗位不是新建一套后台。数班已经把数字员工的公共链路搭好了：人才广场负责雇佣， 数字办公室负责形象与汇报，Agent 设置负责身份与账号范围， 实时工作负责执行，成果中心负责沉淀。 新增一个数字人，就是在这条链路的每个环节各接一次，再补上岗位专属的工作台与对话口径。

  • 复用：平台已有，直接接
  • 改造：公共模块要扩展
  • 新增：新岗位要新建
8个一级模块
47个接入点
4个模块需要新增内容（A / D / E / F）
根节点

新增一个数字人

8 个一级模块、47 个接入点，其中 4 个模块需要新岗位自己填内容。

  1. A

    人才广场

    新增内容

    岗位在这里被看见、被雇佣。卡片机制是平台已有的，新岗位填的是卡片内容和确认弹窗。

    • 岗位卡与岗位详情岗位名、人设、形象图、计费口径
    • 雇佣确认弹窗单页完成雇佣，不再分步
    • 核心依赖检查余额 ≥ 1 次发布单价；至少 1 个账号营销授权有效
    • 账号启用开关开关即工作范围，已完成授权的账号默认开启
    • 计费透出展示实际生效单价与计费规则，不展示"当日预计费用"
    • 雇佣后态岗位卡转"已雇佣 / 查看工作"，员工状态更新为"工作中"
  2. B

    数字办公室

    新增形象

    员工在这里"被看见"。侧栏结构可整体沿用已有岗位，新岗位补的是形象图和汇报口径。

    • 员工形象所有数字员工角色均带形象图，区分雇佣前后
    • 员工状态可雇佣 / 工作中 / 空闲中 / 待处理 / 已暂停
    • 侧栏 · 身份头部头像 + 自定义昵称 + 岗位 + 状态 + 管辖账号数
    • 侧栏 · 工作界面云电脑操作录屏为主视觉，横屏不拉伸
    • 侧栏 · 主动汇报"向老板汇报"口径，须标注统计周期、账号范围、更新时间
    • 侧栏 · 对话区文字输入 + 发送，含进入实时工作与 Agent 设置入口
    • 多员工共存与已有岗位共用同一个数字办公室入口
  3. C

    Agent 设置

    复用

    独立工作区，三要素固定为身份 / 技能 / 权限。这是公共组件，新岗位只需填入自己的技能与账号口径。

    • 入口数字办公室侧栏身份头部、实时工作员工操作菜单
    • 身份区域Agent 称呼 + 人设，只影响表达方式，不改能力与权限
    • 权限区域账号范围：账号名 + 营销授权 + 启用开关 + 最近检查时间
    • 技能区域固定技能表，标"固定 · 由系统维护"
    • 生效规则身份下次任务生效；账号范围保存后生效；执行中任务沿用启动时版本
  4. D

    实时工作

    新增

    一级页面与导航框架复用，岗位专属的工作台在这里新建 —— 这是工作量最大的一块。

    • 模块导航Tab 按岗位定义，顺序贴合该岗位的实际工作流
    • 发布任务四步：选账号 → 选素材 → 发布方式 + 标题策略 → 确认发布
    • 分发与锁定轮询去重分发，一条素材对一个账号；确认时才锁定
    • 执行模型一账号一台云电脑：账号间并行、账号内串行、同账号多任务排队
    • 失败与重试RPA 异常自动重试 3 次；授权 / 文件 / 风控转人工处理
    • 发布结果统一作品明细 13 列 + 四个筛选 + 顶部看板
    • 总览账号卡片一行 5 个平铺；已发布展示最近一次发布视频
    • 作品库两个来源 + 三种素材状态 + 监控账号配置 + 上传校验
    • 规模适配5 / 20 / 50 / 100 账号各自的展示策略
  5. E

    成果中心

    按需新增

    结果沉淀页。做与不做都能成立，取决于该岗位的结果是否需要长期沉淀。

    • 内容效果记录只读；一条作品 × 一个账号 = 一条记录
    • 综合数据看板发布账号数 / 发布作品数 / 累计播放量 / 累计评论量
    • 筛选时间 + 发布账号 + 作品名称，默认最近 30 天
    • 导出14 个字段的 .xlsx，覆盖全部分页
    • 也可以不做不在成果中心新增入口、报表或记录，也是一种成立的边界
  6. F

    对话能力

    新增口径

    对话框架复用，新岗位要定义的是"能问什么"—— 可查询的数据范围与统计口径。

    • 数据查询按账号 + 时间范围查发布情况与内容效果
    • 统计口径完成率、状态分布、效果排名等预计算指标
    • 主动汇报触发条件沿用数字员工统一规则
    • 分段回复查询范围 → 查询结果 → 下一步建议
    • 对话形态二选一员工本人 ／ 岗位组长聚合多账号（一对多账号时用组长）
  7. G

    计费与消耗

    复用

    平台通用能力。新岗位通常只需要选定计费口径，不重定义单价与结算规则。

    • 计费口径按次（例如 ¥2 / 次发布）／ 按日（例如客服专员），两者互不换算
    • 计费单位一次发布 = 一个账号成功发布一条作品；账号数与开启时长不计费
    • 扣费时点发布完成即时扣减；失败不计费，重试成功只计一次
    • 幂等键员工 ID + 账号 ID + 作品标识
    • 消耗明细扣费时间 / 扣费账号 / 发布作品 / 电力值 / 扣费备注
    • 余额不足任务转"待处理"、不执行发布、因此不产生费用
  8. H

    底座与外部依赖

    复用

    岗位不自建，全部沿用平台。这一层如果缺，新岗位是跑不起来的 —— 属于开工前的确认项。

    • 抖音营销授权发布的前置条件，由账号绑定模块承载
    • 云电脑 / RPA一个账号一台，是并行 / 串行规则的物理依据
    • 小班待办失败、授权异常、余额不足的通知落点
    • 权限与审计记录 Agent、修改人、时间、修改项、账号范围、生效范围
怎么用：A / D / E / F 四个模块需要为新岗位填内容，是排期的起点； B / C / G / H 是平台已有能力，逐条确认"接得上"即可。
