## 一、口径裁决

### 1. 试用与重置

- 试用**发放**不重置低消周期，不重置 365 天到期时间。
- 试用客户**付费**时：重置低消 31 天周期（以付费时间为起点），并按「付费充值」默认带出 365 天。
- 付费状态客户**周期内续费**：不重置周期起点。
- 周期**已到期后**再充值：以再充值时间为新起点。
- **落点**：PRD §4.1 / §2.7；后台 `openVipEdit`；客户侧周期文案

### 2. 单笔上限

- 单笔充值、单笔电力值调整 ≤ 100,000 电力值。
- 余额总额不设上限；负值方向不设下限。
- **落点**：PRD §5.2 / §10.1；后台 `openVipEdit` 输入校验（只校验单笔）

### 3. 负余额与阻断

- 余额为负：**新业务停止**；**未结算的照常结算扣费**，余额可继续变负。
- 负数是合法中间态（获客专家等岗位 T+1 结算）。
- 门禁判断在**业务受理入口**，不在结算链路。
- 客户侧阻断弹窗须注明「新业务已停止，在途消耗仍会继续结算扣费」。
- §5.2「负余额不阻断业务执行」拆为两句：**不阻断结算** + **阻断新业务**。
- **落点**：PRD §5.2 / §7.3；客户侧门禁与弹窗

### 4. 行业默认套餐

- 每个行业**恰好一个**默认套餐，系统预置，**不可为空**。
- 审核时**必须选套餐**，默认选中本行业默认套餐。
- 行业默认套餐**不可删除**。
- **落点**：PRD §2.4 保持原样；§2.5 / §10.4 补审核必选；§10.3 删除保护

### 5. 低消标准值

- 低消 = **500 电力值**；演示数据里的 1200 全部替换。
- **落点**：PRD §2.4 预置清单；后台 `monthlyMinimumOf`；客户侧 `monthlyMinimum`

### 6. 套餐包名称

- 本期沿用「套餐包」，不改名。
- **落点**：PRD §13 挂「名称待定」一条

## 二、套餐包与行业

### 7. 套餐所属行业（单选）

- 一个套餐只属于一个行业。
- 套餐包列表增加「所属行业」列 + 行业筛选；新增 / 编辑弹窗增加「所属行业」单选。
- **落点**：PRD §2.2 / §2.4 / §10.3；后台 `packages`、`renderPackages`、`openPkgEdit`

### 8. 行业下的多个套餐

- 同一行业可以有多个套餐，其中**指定一个为行业默认**（每组至多一个）。
- 「设为默认」的下拉不列出已作为默认的套餐。
- **落点**：PRD §2.4 / §10.3；后台新增「设为行业默认」入口，`industryPackage` 语义调整

### 9. 审核必选套餐

- 注册审核时运营必须选一个套餐；本行业已有默认套餐时预选它，可改。
- **落点**：PRD §2.5 / §10.4；后台注册审核页

### 10. 门店改套餐的下拉范围

- 只列门店所属行业下的套餐；去掉「未关联（跟随行业默认套餐）」选项。
- **落点**：PRD §2.5 / §10.4；后台 `#pkgSelect` 选项生成

### 11. 套餐删除保护

- 行业默认套餐不可删；有账号在用的不可删。
- 套餐没有启用 / 停用概念，只有关联关系。
- **落点**：PRD §10.3 / §10.6 验收；后台 `usageOf`、`openPkgDelete`

### 12. 门店改套餐后的口径

- 整包生效，不再回看行业默认套餐（维持现行）。
- **落点**：PRD §2.5 保持原样

## 三、高级结算

### 13. 高级结算开关

- 关闭时**保留配置**，只是不生效；重开不需要重填。
- **落点**：PRD §3.2 / §3.3 / §10.1；后台 `senior-save` 关闭分支、`openSeniorConfig` 回填

---

## 四、低消周期

### 14. 周期起算

- 到账当天不计入，次日起算 31 天，末日运行到 23:59:59（等价于到账日 + 32 天的 00:00 结束）。
- **落点**：PRD §4.1 / §4.4 验收；两个原型的 `cycleEndAt` 计算与演示数据

### 15. 冻结与解冻

- 冻结期间不结算、周期不推进；解冻后重新起算 31 天（维持现行）。
- **落点**：PRD §4.1 / §5.3 保持原样

---

## 五、充值类型

### 16. 字段

- VIP 编辑增加「充值类型」与「备注」。
- 类型四类：付费充值 / 赠送 / 延期付费 / 试用；原「运营补发」并入「赠送」。
- **落点**：PRD §2.7 / §10.1；后台 `openVipEdit`、`recharges`

### 17. 类型对时间的作用

- **付费充值、延期付费**：重置低消周期起点与 365 天到期时间。
- **赠送**：不重置。
- **试用**：发放不重置；试用客户付费时按付费充值处理。
- **落点**：PRD §2.1 / §2.7 / §4.1 / §5.3；后台 `vip-save`

### 18. 默认天数

- 弹窗按类型默认带出天数：重置类型默认 `365`，不重置类型默认 `0`，运营可改。
- 不做后端重置判断。
- **落点**：PRD §10.1；后台 `openVipEdit`

### 19. 备注文案

- 按类型生成：「付费充值到账 / 赠送到账 / 试用到账 / 延期付费到账」；有抵扣负值的追加「抵扣 N 电力值」；负数调整仍为「VIP 调整，扣减电力值」。
- 客户侧与后台口径一致。
- **落点**：PRD §2.7 / §6.4 / §6.5 验收；两侧充值记录表

---

## 六、试用 / 付费状态

### 20. 状态与到期时间

- 后台门店增加「试用中 / 付费中」状态，人工切换。
- 到期时间拆为「试用到期时间」「付费到期时间」两个字段，按当前状态生效。
- **落点**：PRD §5.1 / §10.1 / §10.2；后台 `stores`、门店列表状态列、VIP 编辑

### 21. 状态切换的基准

- 试用 ↔ 付费切换时，新状态的到期时间 = 当日 + 365（可调），不在旧到期时间上叠加。
- **落点**：PRD §10.1；后台 `vip-save`、`openVipEdit`

### 22. 本期范围

- 试用 / 付费状态只做后台，客户侧不做区分。
- **落点**：PRD §6.4 注明本期不做

---

## 七、到期时间调整

### 23. 调整基准分两种

- 付费状态**不变**：基准 = 当前到期时间，结果 = 到期时间 + N 天。
- 付费状态**变更**（试用 ↔ 付费）：基准 = 当日，结果 = 今天 + N 天。
- 「预计到期时间」按当前所选基准实时计算并展示。
- 「当前到期时间」保留展示，并作为状态不变时的计算基准。
- **落点**：PRD §10.1 / §10.2；后台 `openVipEdit` 预览与 `vip-save`

---

## 八、客户侧展示

### 24. 有效期露出

- 客户侧要能看到有效期，不只在电力账户弹窗内。
- **落点**：PRD §6.4 / §6.5 验收；客户原型顶栏余额入口区域

### 25. 阻断弹窗

- 两种原因：服务期到期、余额为负。任一满足即弹，写明原因与「在途消耗继续结算」。
- **落点**：PRD §7.3；客户原型新增弹窗组件

### 26. 充值记录文案

- 备注按类型显示，与后台一致。
- **落点**：PRD §6.4 / §6.5 验收；客户原型充值记录表

### 27. 「本周期」文案

- 必须含周期起止日期与本期最低消费额。
- **落点**：PRD §6.4；客户原型低消卡片

### 28. 消费明细

- 保留「全部」视图承载低消结算与负数抵扣；通用字段统一为 扣费时间 / 数字员工 / 扣费账号 / 电力值 / 扣费备注（维持现行）。
- **落点**：PRD §9.1 / §9.2 保持原样

- 不做。后续由运营侧自建看板，后端需提供「每个客户的余额表」。
- **落点**：PRD §7.1 / §7.2；§13 挂接口需求

### 30. 余额阈值提示

- 不做。
- **落点**：PRD §7.1

### 31. 订单审核

- 不做。充值走线下 + 后台登记；用户端只保留申请（维持现行）。
- **落点**：PRD §6.2 保持原样

## 十、其他

### 32. 试用余额的清理

- 试用余额与付费余额同一个字段；付费时由运营在余额调整里手动处理（如需清零则少记：充 5000、试用剩 500 → 记 4500）。
- **落点**：PRD §6.2 / §10.1 写操作口径；后台不改逻辑

### 33. 套餐包与员工解绑不联动

- 套餐只是员工单价：用了按此收费，不用不收费（维持现行）。
- **落点**：PRD §2.5 保持原样

### 34. 运营后台视觉重排

- 入口不要太深，重新排布；组件与风格严格沿用中台。
- **落点**：后台原型（不改业务逻辑）
